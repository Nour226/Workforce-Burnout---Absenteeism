# Workforce Burnout & Employee Absenteeism: Role A package (data engineer)

PostgreSQL database, data generator, loader, KPI SQL and an automatic acceptance test for the three decisions in our KPI matrix.

## 1. content

| Path | What it is |
|---|---|
| `sql/01_schema.sql` | 5 tables, keys, constraints, indexes (re-runnable) |
| `scripts/generate_data.py` | Builds the 4 CSV files (hybrid: IBM HR base + synthetic rules), seeded |
| `scripts/load_data.py` | Creates the schema, loads the CSVs with `COPY`, creates the KPI views |
| `sql/02_kpi_queries.sql` | KPI 1, KPI 2, KPI 3 as views and one function |
| `sql/03_quality_checks.sql` | Data-quality report (every violation count = 0) |
| `scripts/verify_kpis.py` | 32 checks: SQL results recomputed independently in Python, plus dataset properties |
| `verification_report.txt` | Output of the last verification run (32/32 passed) |
| `run_all.sh` | Runs everything in order |
| `data/*.csv` | The generated data (what is loaded in the database) |
| `database/absenteeism_dump.sql` | Full dump of the finished database (restore with `psql`) |

## 2. How to run it (about 10 minutes)

1. Install PostgreSQL 14+ and Python 3.10+. Then: `pip install pandas numpy "psycopg[binary]"`
2. Create the database: `createdb absenteeism`
3. Set the connection (Windows PowerShell: `$env:PGHOST="localhost"`, etc.):
   `export PGHOST=localhost PGPORT=5432 PGUSER=postgres PGPASSWORD=... PGDATABASE=absenteeism`
4. Download the real IBM file from https://www.kaggle.com/datasets/pavansubhasht/ibm-hr-analytics-attrition-dataset (Kaggle login needed). The CSV is `WA_Fn-UseC_-HR-Employee-Attrition.csv`.
5. Run: `./run_all.sh path/to/WA_Fn-UseC_-HR-Employee-Attrition.csv`
   Without the path, the script builds a stand-in with the same columns and approximate IBM distributions.
6. Success looks like: `32/32 checks passed` at the end.

Restore only the finished database instead: `createdb absenteeism && psql -d absenteeism -f database/absenteeism_dump.sql`

## 3. Data model

| Table | Rows | Columns |
|---|---|---|
| `departments` | 3 | dept_id, dept_name |
| `employees` | 1,470 | employee_id, full_name, dept_id FK, job_role, gender, age, distance_from_home, hire_date |
| `employee_managers` | 1,470 | employee_id FK, manager_id FK (self), separated from employee profile data |
| `weekly_workload` | 76,093 | workload_id, employee_id FK, week_start (Monday), hours_worked, overtime_hours (computed: hours above 40) |
| `absences` (main) | 39,039 | absence_id, employee_id FK, start_date, end_date, weekday (computed), absence_type (`Planned leave` / `Unplanned`), reason, is_justified |

Period: 52 weeks, 2025-01-06 to 2026-01-04. Each generated absence row currently represents one working day, so `start_date` and `end_date` are equal; the schema supports multi-day ranges.

## 4. KPI matrix to SQL

| # | Decision | KPI | Object | Logic |
|---|---|---|---|---|
| 1 | Proactive workload reallocation | Average overtime per department | `v_kpi1_overtime_by_dept_month` | `AVG(overtime_hours)` and `SUM(overtime_hours) / COUNT(DISTINCT employee_id)`, grouped by department and month |
| 2 | Early burnout detection | Burnout alert score | `fn_burnout_alerts(as_of, hours, weeks, leave_days)` (defaults 50 h, 4 weeks, 90 days) | More than 50 h in each of the last 4 consecutive weeks AND 0 planned-leave days in the last 90 days |
| 2 | (diagnostic) | Past 4+ week streaks | `v_kpi2_streak_history` | Gaps-and-islands with `ROW_NUMBER()` |
| 3 | Wellbeing plan and management | Unplanned absence rate | `v_kpi3_unplanned_rate_by_manager_weekday`, `v_kpi3_by_weekday`, `v_kpi3_by_manager`, `v_kpi3_reason_by_weekday` | Unplanned absence days / total working days (team size x number of that weekday in the period), by weekday and manager |

## 5. What the dataset is, for your data-source section

> Hybrid dataset. Employee profiles come from the IBM HR Analytics Employee Attrition & Performance dataset (Kaggle, 1,470 rows, itself an artificial dataset published by IBM). The manager hierarchy, weekly working hours and daily absences do not exist in any public dataset, so they were generated by `generate_data.py` (seed 42), driven by the IBM fields OverTime, WorkLifeBalance and JobSatisfaction, with weekday, season and manager effects. Findings describe the generated data.

## 6. Results (last verification run)

- All 3 SQL KPIs equal an independent pandas recomputation: 36 department-month cells, 615 manager-weekday cells, and the alert list for 3 different parameter sets.
- KPI 1: Sales highest (3.35 h/week average overtime), Human Resources lowest (2.51); max/min across department-months = 2.49.
- KPI 2: 61 alerts (4.1% of employees); another 34 employees have the streak but took leave, so both conditions matter. Alerted employees average 9.2 unplanned days vs 6.4 for others.
- KPI 3: unplanned rate Mon 2.82%, Tue-Thu about 2.26%, Fri 3.08%; manager rates range from 0.82% to 5.28% (median 2.54%).
- The tests were also checked to fail when the SQL is deliberately broken.

## 7. Limits you must state (honest list)

- The verification above ran on the **stand-in** (IBM structure, approximate distributions), because Kaggle could not be downloaded in the build environment. The `--ibm` path was tested with an IBM-shaped file and also passed 32/32. **Run once with the real CSV and keep that report** (`verification_report.txt`).
- Hours, absences, managers and the burnout propensity are synthetic and reflect my assumptions. The UCI Absenteeism file was not read by the code: the reason categories and the Monday/Friday and winter patterns are inspired by it, not computed from it. If your teacher expects UCI calibration, compare its weekday and reason shares with `v_kpi3_by_weekday` and `v_kpi3_reason_by_weekday` and adjust the factors in `build_unplanned`.
- The week is Mon-Fri (as in the brief's Monday/Friday effect) and public holidays are not modelled. Algerian working weeks differ; change the weekday logic if your teacher cares.
- A week counts for the month of its Monday. The last employee-week of the year (2025-12-29) ends on 2026-01-04.
- Manager-level KPI 3 covers each manager's team, not the manager's own absences.
- About 0.45% of employee-weeks are deliberately missing, so a missing week breaks a streak. Mention it in the open-issues section as a real data-quality case.
